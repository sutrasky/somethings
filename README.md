# somethings

各生产环境的计划文档与其他文件归档。一个环境一个顶层目录，目录内结构统一。

## 目录约定

```
README.md          本文件：环境清单与索引
template/          新环境模板，复制一份改名即可
<环境名>/           一个环境一个目录，例如 prod-cn、prod-us、staging
  README.md        环境说明：入口、账号归属、注意事项、变更记录
  plans/           计划文档（方案、排期、上线清单、回滚方案）
  artifacts/       其他文件（配置导出、截图、报表、脚本）
```

## 环境清单

| 环境 | 目录 | 用途 | 最近更新 |
| --- | --- | --- | --- |
| （示例）生产-华东 | `prod-cn/` | 主站生产环境 | 2026-11-19 |

新建环境时把上表补一行。

## 新增一个环境

```bash
cp -r template prod-<环境名>
```

然后改 `prod-<环境名>/README.md` 里的环境说明，并更新本文件的「环境清单」。

## 计划文档命名

`plans/YYYY-MM-DD-<主题>.md`，例如 `plans/2026-11-19-灰度发布方案.md`。
日期用该文档的生效（或创建）日期，便于按时间排序。

## 硬性规则

- **不放密钥**：密码、私钥、令牌、`.env`、带凭据的配置一律不入库；需要记录时只写「在哪台机器的哪个路径」。
- **不放大文件**：单文件超过 10 MB 的（数据库导出、镜像）不放仓库，仓库里只放说明和外部存储位置。
- 客户数据、个人信息先脱敏再提交。
- 提交信息写清环境与动作，例如 `prod-cn: 补充 12 月扩容计划`。
